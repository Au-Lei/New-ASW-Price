# 任务七：真实文件上传与提取任务

日期：2026-10-25。仅本阶段实现及验收；任务八未开始。

## 功能与范围

- 新增“更新报价 → 上传原件与提取报价”。可选择多个原件，逐文件保存并返回各自成功／失败原因，部分失败不会丢弃已成功保存的原件。
- 支持xlsx、pdf、jpg、jpeg、png。扩展名与内容联合校验：xlsx解析OOXML结构，拒绝损坏、加密、宏及外部工作簿链接；PDF校验结构、加密与页数；图片校验签名、实际类型及完整解码。xls提示另存xlsx。
- 默认单文件20MB、单批10个、PDF最多50页；后端配置可调整。图片最多4000万像素，拒绝多帧图片。原有Excel解压大小、成员数、工作表／行／列范围保护继续适用；不执行公式、外部链接、宏或附件中的指令文字。
- 原文件使用随机文件标识保存在`data/uploads/`，原名、真实媒体类型、大小、SHA256及元数据入库。文件名不决定磁盘路径。上传写库失败会回收本次未入库文件；重复内容提示并复用原件记录。
- 原件不放静态资源目录，下载经过后端操作员和批次归属检查。下载强制附件、nosniff及no-store，阻止文档作为网页内联执行；图片预览通过受检原件生成本地对象URL。草稿、审批和版本历史可下载来源原件，保留单元格定位。
- 点击“提取报价”后登记持久任务。等待、处理中、成功、失败状态与尝试次数／错误原因保存；同文件重复点击复用同一任务。前端在有活动任务时自动刷新，离开页面不会取消后台任务。
- 后台使用单进程内单个工作线程与SQLite写事务领取任务。结果、导入预览、任务成功状态及尝试记录在同一事务落库。结果保存失败回滚并标记失败，可重试。
- 重启时等待任务继续执行，处理中任务记录中断并重新排队；独立运行令牌隔离旧执行，防止旧线程结果写入恢复后的任务。每次提取尝试分别保留，重试不覆盖已有尝试记录。
- 固定Excel模板复用既有真实解析器，保留逐行原文、归一字段、校验问题、工作表及单元格位置。提取成功只是得到待校对预览，不自动生成草稿或正式报价；需用户选择行生成草稿，再人工校对和审批。一个上传批次支持多份Excel，原有历史导入记录迁移后保留。
- 草稿和来源证据关联提取任务ID；人工编辑与原始提取结果分别存储。已提交审批的批次不能再追加草稿；写入草稿更新批次修订号，旧对比令牌会失效。

## AI与身份边界

本轮没有配置或调用外部AI，也没有将业务原件外发。PDF、图片及不符合固定模板的Excel可真实上传、校验、保存和下载，但点击提取会明确失败：`AI_NOT_CONFIGURED`，保留原件及重试路径。PDF／图片识别与其他表格结构化属于任务八，没有用模拟结果代替。

继续沿用任务六的服务端固定本机管理员模式。原件和任务接口已做服务端有效操作员、管理员／本人批次访问判断；业务身份与伪造角色请求头的拒绝测试通过。尚不宣称有真实登录认证，账号、会话及完整权限在任务九接入。继续只监听127.0.0.1。

当前恢复设计适用于既定单进程启动方式；不支持同时启动多个worker进程管理同一队列。未来若增加多进程部署，需另行设计跨进程租约和恢复协调。
